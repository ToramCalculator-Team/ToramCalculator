# 6 通信事件循环

[返回译文目录](actor-systems-translation.md)

Vulcan[26] 是一种并发面向对象逻辑编程语言，同样受到 Hewitt 的 Actor 计算模型启发。它由 Kahn 等人于 1986 年在 Xerox PARC 开发，是 Concurrent Prolog 的预处理器。20 世纪 80 年代，Dean Tribble 曾在 Xerox PARC 实习；1994 年，他开发了分布式编程语言 Joule。Joule 是 Mark Miller 后来开发的 E 语言[29]最直接、最重要的前身。E 是第一个引入通信事件循环 Actor 模型的语言。

与活动对象模型类似，通信事件循环（CEL）模型采用双层结构，Actor（在 E 中称为 vat）与对象共存。不过，它与活动对象模型有一项重要区别：它不区分被动对象和活动对象。Actor 没有一个作为入口的单一活动对象；事实上，Actor 本身甚至不是一等实体。相反，Actor 可以直接持有其他 Actor 堆中对象的引用。在 Actor 内部，指向本 Actor 所有对象的引用称为近引用（near reference）；指向其他 Actor 所有对象的引用称为远引用（far reference）。引用的类型决定 Actor 的执行线程可以对被引用对象执行哪些访问操作。Actor 可以获得另一 Actor 所有对象的直接引用（远引用），但不能通过该引用立即调用对象。通常，Actor 通过交换地址彼此引入；在 CEL 模型中，地址总是指向特定对象的远引用，该对象定义了其他 Actor 可用来与之交互的接口。

CEL 与前述 Actor 模型的主要区别在于：其他模型通常只向一个 Actor 提供单一入口或地址，即任一时刻 Actor 只能有一个接口；CEL Actor 可以定义多个对象，这些对象共享同一邮箱和控制线程，并将不同对象的引用分发出去。因此，可以让一个 Actor 同时拥有多个接口。这种设计有助于遵循最小权限原则（PoLP）[30]：通过许多细粒度的对象级接口，而不是单一的大型 Actor 级接口来控制访问。清单 1.5 展示了在 E 中创建对象并向它异步发送 `get` 消息。

当一个 Actor 中的对象向另一个 Actor 的对象发送异步消息时，消息会进入接收对象所有者的邮箱，并立即返回一个 promise。消息处理后，promise 会以消息的返回值完成。Actor 不允许将 promise 作为近引用使用。若 Actor 想立即对 promise 所代表的值进行操作（例如打印），就必须设定在 promise 完成时执行的动作，可使用 `when` 原语。`get` 消息对应的 promise 完成后，`when` 的消息体就会执行；在执行过程中，promise 已解析，可以像本地对象一样使用。

E 中的 promise 基于 Argus 的 promise[28]，主要区别在于：Argus 中访问 promise 是阻塞操作，而 E 采用纯异步模型，执行 `when` 也是异步操作。

```text
def cell {
  var contents := null
  to put(newContents) {
    contents := newContents
  }
  to get() {
    return contents
  }
}
var promise := cell<-get()
when (promise) -> {
  println(promise)
}
```

**清单 1.5：** E 中的 Actor。

通信事件循环模型后来也被 AmbientTalk[37]采用。AmbientTalk 是面向对象的分布式语言，旨在为移动自组织网络开发应用，并作为环境定向编程（AmOP）语言设计[16]。它为 Actor 模型增加了一些处理网络节点断开与重新连接的原语，以应对不稳定的连接；其核心并发模型仍忠实于 E 的通信事件循环。

## 6.1 操作语义

通信事件循环模型中，每个 Actor 由标识符 `ιa`、邮箱 `μ`、当前表达式 `e` 和对象堆 `O` 表示。与活动对象模型不同，没有单一活动对象作为 Actor 的入口。Actor 可以将自身堆中对象的远引用共享给其他 Actor。远引用由 `ιa.ιo` 表示，同时标识对象及其所有者 Actor。其他 Actor 可以通过这些远引用发送异步消息，因此任一远引用都能成为进入某个 Actor 的入口。被引用对象的接口在 Actor 生命周期内保持不变。Actor 可以拥有多个固定接口；消息带有额外的对象标识符 `ιo`，用于标明目标 Actor 堆中的接收对象。

程序仍由类定义集合构成，`Main` 类实现 `run` 方法；类、方法和表达式语法与活动对象模型相同。初始配置包含一个主 Actor、一个 `Main` 类对象，并以同步调用该对象 `run` 方法的表达式启动。

### Actor 局部归约

Actor 持续取出邮箱中的第一条消息并处理。收到的消息会通过同步调用转发给目标对象。调用表达式完全归约后，才能处理下一条消息；因此，与经典 Actor 和进程模型不同，消息总是按顺序处理。如果邮箱首条消息与目标对象接口不匹配，或表达式无法继续归约，则程序停滞并表示错误。唯一合法的不可归约状态是当前表达式已成为值且邮箱为空，此时 Actor 空闲等待新消息。

主要局部规则如下：

- **LET：** 将值代入表达式中的变量。
- **NEW：** 新对象归创建它的 Actor 所有，并加入其堆；表达式归约为该对象的远引用。
- **INVOKE：** 根据远引用定位本地对象，并在对应类中查找方法；方法体中的 `self`、字段和参数分别替换为对象引用、字段值和消息参数。
- **FIELD-ACCESS / FIELD-UPDATE：** 在本地对象堆中读取或修改字段。
- **SELF-SEND：** 向自身对象发送异步消息，将消息追加到本 Actor 邮箱，发送表达式归约为 `null`。
- **RECEIVE：** 从邮箱头部取出消息，使用目标对象标识符和消息名构造该对象上的方法调用。

### Actor 全局归约

- **CREATE：** 创建 Actor，并用新建对象作为其初始对象；参数中传递的对象通过深拷贝保持隔离。新 Actor 以空邮箱及空闲表达式初始化，创建表达式归约为新 Actor 的引用。
- **SEND：** 异步消息被加入接收对象所有者 Actor 的邮箱，并携带目标对象标识符；发送表达式归约为 `null`。
- **CONGRUENCE：** 将局部归约规则连接到系统配置归约规则。

CEL 模型的可变对象属于创建它们的 Actor。Actor 之间传递对象时，会传递远引用而非共享可变对象内容。对象消息针对特定目标；若目标对象不理解该消息，Actor 会停滞，表示程序错误。顺序子集采用命令式范式。远引用使 Actor 能够与另一个 Actor 的对象通信，同时保持执行由对象所有者 Actor 的事件循环串行处理，因此模型满足隔离回合原则。

## 6.2 总结

通信事件循环模型的特征是 Actor 与对象构成的双层编程模型。Actor 不是一等实体。一个 CEL Actor 可以定义多个共享同一邮箱与控制线程的对象，并分发指向这些对象的不同引用。这使 Actor 能同时拥有多个接口，便于采用最小权限原则（PoLP）组织程序。虽然一个 CEL Actor 可以拥有多个接口，但这些接口都是预先确定且固定的。

## 7 总结

Actor 计算模型的核心是一个简单的编程模型，其中心概念是 Actor。Actor 是彼此隔离、通过异步消息传递通信的进程。这种严格隔离与异步通信的主要优点，是能够避免低层数据竞争和死锁。本文将此定义为所有 Actor 系统的关键共同原则，并称为隔离回合原则。不过，半个世纪的研究带来了大量性质各异的 Actor 模型变体。

本文聚焦总体编程模型，并提出四个可用于分类 Actor 系统的广泛家族：经典 Actor、活动对象、进程和通信事件循环。本文简述了实现这些 Actor 模型家族的一些重要编程语言与库的历史；这些系统影响了并将继续影响当今其他 Actor 系统的设计与理念。本文也通过操作语义，为四个 Actor 家族的核心子集提供了精确形式化定义。相应的可执行 PLT Redex 版本已公开。隔离回合原则是统一所有 Actor 系统的核心原则，但 Actor 系统还可以按照许多其他性质分类。尽管这些性质很大程度上取决于具体实现，仍可得出以下一般结论：

- 经典 Actor 与进程模型的顺序子集通常是函数式的；活动对象与通信事件循环通常是命令式的。只要遵守隔离回合原则，范式选择并不实质影响系统的并发性质。
- 经典 Actor 与进程拥有灵活接口，有利于条件同步；活动对象与通信事件循环拥有固定接口。通信事件循环是唯一支持 Actor 创建多个细粒度接口的模型，因此适合采用最小权限原则的编程方式。
- 接口灵活的 Actor 模型通常支持乱序处理消息；接口固定的模型通常按照 FIFO 顺序处理消息。
- 顺序子集采用的范式直接决定 Actor 级别的状态变化是如何聚合的：函数式语言会聚合状态变化，命令式语言则逐变量改变状态。
