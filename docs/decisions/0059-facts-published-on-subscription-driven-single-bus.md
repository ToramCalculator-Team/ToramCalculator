# 0059 - 对外事实由订阅驱动并从唯一引擎事件总线发布

- **状态**: Accepted
- **日期**: 2026-10-14
- **决策层**: 跨层（引擎 / 通信 / 应用）
- **相关代码**: `src/engine/core/Event/EventCatalog.ts`、`src/engine/core/Event/BuiltInEvents.ts`、`src/engine/core/World/Member/ProcBus/`、`src/engine/core/DomainEvents/`、`src/engine/core/World/`、`src/engine/core/thread/`
- **相关 ADR**: Supersedes 0011；Refines 0010；Refines 0050

## 决策问题

引擎内部各过程会在运行中产出「发生了什么」的事实：结算点产生受击与致死，状态实例产生进入与离开，技能效果行为树产生治疗与施法完成，状态机产生目标选择与施法接纳。成员内的被动与 buff 需要响应其中一部分，引擎外的消费者需要感知另一部分。

当前成员内响应走一条成员私有总线，对外观察走另一条引擎级投影总线，并约定同一结算点成对派发。需要决定：事实的发布与对外交付之间是什么关系，以及成员内响应与外部观察是否应共用同一套发布与订阅模型。

## 决策驱动

- 引擎是无消费者也必须正常运行的模拟器。没有任何观察者时，产出对外数据不应有成本。
- 事实的发布是过程的职责；是否需要向外交付是消费者的需求。前者不应由后者决定。
- 成员内响应与外部观察对同一事实的兴趣只差在作用域，不应维护两套事件词汇表和两套订阅模型。
- 对外交付的载体是容量有限的共享通道，超限必须显形失败，不能被静默丢弃或覆盖。
- 属性与状态投影是数值的权威来源；已发送的事实不应成为第二份可独立演化的数值来源。
- 发布点必须唯一。同一事实存在两个发布点时，对其中一个的补充必然被遗忘，而缺失在事后无法发现。

## 候选方案

### A. 权威结算点成对派发到两条总线

- 优点：成员内与对外各自持有适配的负载形状，两条通道的职责表面上清晰。
- 缺点：同一事实有两个发布点，只能靠调用约束维持一致；外部交付与事实产生耦合，没有消费者时仍要收集与写出；事件词汇表出现两套，同一事实在两个载体上叫不同名字。

### B. 唯一发布总线，订阅决定交付

- 优点：过程只发布一次；作用域由订阅声明表达；没有订阅者时不产生任何对外数据，模拟结果不变；对外载体只承载「发生了什么」，数值保持在状态载体中作为单一来源。
- 缺点：总线需要显式区分作用域并相应分桶，否则派发退化为全量扫描；订阅表成为必须正确清理的生命周期资源。

### C. 现状保留，只给对外投影总线增加消费者配置

- 优点：改动最小，只影响投影侧。
- 缺点：没有解决发布与交付的耦合，也没有统一两套词汇表；消费者从一到多时，投影总线仍需自重写所有权与容量规则。

只记录当时真实可行且实际考虑过的方案。

## 决议

选择 B：**引擎持有唯一常设事件总线；过程自发发布「已发送的事实」；订阅只决定哪些事实需要对外交付。**

- 发布是过程的职责，与是否存在订阅者无关。总线的存在不依赖任何订阅者。
- 订阅决定对外交付。没有任何订阅者时，引擎不产生、不收集、不写出任何对外数据，且模拟结果与存在订阅者时逐 Tick 一致。
- 事实只承载「发生了什么」：事实身份、涉及主体与模拟时刻。事实不携带数值负载。需要数值的消费者从状态载体读取；状态载体现有表达力不足时，扩展状态投影，而不是把数值放回事实。
- 拒绝也是一种事实。被拒绝的尝试与被接纳的转移在同一载体上发布，不为「未发生」另立通道。
- 成员内响应与外部观察是同一总线上的两种作用域，共用同一份事件词汇表。成员私有总线和对外投影总线合并为一条引擎级总线。
- 事实的发布点是有权产生该事实的过程本身。承载外部意图的入口不是事实发布点：进入引擎的意图属于输入记录，与向外的已发送事实是不同的数据产品，两者不共用名称。
- 订阅是显式声明，不是隐式默认。未声明的观察点不产生数据。交付节奏由消费者决定；不需要逐次观察的消费者可以只取最新值。

## 代价

- 总线必须按作用域分桶并承担订阅表生命周期，实现复杂度高于成员私有总线。成员移除时其作用域的订阅必须显式清理。
- 对外交付与事实收集解耦后，「这次运行记录了哪些事实」由订阅声明决定，读取方必须能确认实际生效的订阅范围。
- 消费者若要同时得到「发生了什么」与「是多少」，必须同时订阅事实载体和状态载体，跨载体关联成为消费者职责。
- 事实与数值分离会把部分分析需求转化为状态投影的列扩展需求。
- 事件词汇表成为对外契约的一部分，词汇变更需要按兼容性处理，缓存与校验都必须随词汇版本化。

## 重新评估条件

- 出现同一事实必须携带数值，而状态载体无法表达、且扩展状态投影在性能或结构上不可行的场景。
- 对外消费者出现必须区分「已发送」与「已被处理」的需求，使订阅从投递语义变为确认语义。
- 成员作用域的事实需要稳定的跨成员传播语义，使单条总线的作用域模型不再成立。
- 单个 Tick 内的订阅者规模使按作用域分桶的派发仍超出运行预算。
