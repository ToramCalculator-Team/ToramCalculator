# 0053 - 成员逻辑状态输出与渲染映射边界

- **状态**: Accepted
- **日期**: 2026-08-16
- **决策层**: 跨层（逻辑引擎 / Worker / 线程协议 / 渲染）
- **相关代码**: `src/engine/core/thread/worldStateBuffer.ts`、`src/engine/core/thread/Simulation.worker.ts`、`src/engine/core/World/Member/`、`src/platform/render/scene/`
- **相关 ADR**: Refines 0016；Depends on 0027；Depends on 0050；Refines 0052

> 2026-08-20 修订：将本文收敛为逻辑状态与渲染映射的职责边界；删除状态槽字段、状态枚举、具体 API 和逐文件迁移等实现细节。动态阶段进度仍由渲染层依据逻辑时间和本地资源计算。

## 决策问题

逻辑引擎需要向渲染层提供成员的当前动作状态。技能流程由行为流程动态编排，步骤可以插入或中断，因此不能把技能阶段固化为固定的生命周期模型；同时逻辑引擎不应知道动画名称、时长或播放方式。需要决定逻辑状态如何产生、如何汇合，以及实时状态共享通道只传输什么。

## 决策驱动

- 技能流程可变：行为树负责执行流程，步骤可以动态插入或中断。
- FSM 已经保证成员级动作互斥，并在离开技能状态时中断当前技能行为流程。
- 逻辑引擎与渲染层必须独立：动画映射、播放策略和逐帧表现属于渲染层。
- 实时状态是 latest-state 语义，渲染器只读取最新提交并允许跳过中间状态。
- 当前表现必须能从一个一致的实时状态提交和本地资源映射重建。

## 候选方案

### A. FSM 作为唯一视觉状态来源

BT 把流程阶段变化发回 FSM，由 FSM 统一发布状态。

- 优点：渲染输入来源单一。
- 缺点：FSM 必须预定义任意动态技能步骤，或者退化为通用状态转发槽；BT 到 FSM 的反向依赖增加一层传递；动态插入步骤需要同步修改 FSM 事件面。

### B. FSM 与 BT 分别发布视觉状态到渲染层

渲染器同时接收两个来源并自行裁决。

- 优点：不改变现有逻辑控制关系。
- 缺点：渲染层知道逻辑内部结构；需要定义跨线程的冲突与优先级语义；与“渲染器只解释状态”的边界冲突。

### C. FSM 与 BT 在引擎内汇合为每帧单一状态输出

FSM 和 BT 都声明逻辑状态，由成员投影器按结构规则选择最终状态，Worker 把最终状态写入 SAB。

- 优点：BT 保持动态技能流程；FSM 保持成员生命周期；渲染器只消费一个状态帧；冲突由 FSM 既有互斥和中断规则消化。
- 缺点：需要在引擎内建立状态汇合边界，并约束只有承担成员当前动作语义的行为流程可以声明动作状态。

## 决议

选择 C：**逻辑引擎持续输出成员的语义动作状态；成员生命周期与行为流程在引擎内汇合为单一的当前状态，渲染器依据该状态、逻辑时间和本地资源映射计算当前表现。**

确立以下不变量：

1. 逻辑引擎不输出动画资源事实或逐帧播放指令。实时状态只提供足以解释当前逻辑表现的语义信息；具体载体由代码契约决定。
2. 成员动作状态必须具有稳定的语义身份和可判断的连续声明边界，使渲染器能识别状态切换与重新进入；字段和编码方式不由本 ADR 规定。
3. 状态目录表达通用逻辑语义，而不是具体动画片段。目录由引擎与渲染资源共同遵守，扩展时保持跨层语义一致。
4. 成员生命周期状态是动作状态的权威裁决者；行为流程可以在其允许的范围内细化当前状态，但不能绕过生命周期的中断和互斥规则。
5. 只有承担成员当前动作语义的流程可以声明动作状态；声明使用语义概念，不接收动画名称、时长或播放倍率。状态持续到下一次声明、流程结束或生命周期中断。
6. 最终状态选择由成员生命周期与当前行为流程的既有裁决关系决定，不在渲染层复制一套全局优先级或分支算法。
7. 位置、朝向、速度、移动和腾空是物理事实，与动作状态保持独立。
8. 渲染器维护逻辑状态到动画片段与播放策略的本地映射，并结合逻辑时间计算当前表现，包括需要动态推进的咏唱、蓄力、前摇和后摇进度。
9. 动作状态是逐 Tick 派生的输出事实，不是独立持久化状态；恢复成员生命周期和行为流程后，由逻辑层重新产生当前状态。
10. 本 ADR 补充 0052 的成员逻辑状态与渲染映射边界，不改变 0052 关于连续状态、离散事件、静态资源和历史数据的通道决策。

## 代价

- 渲染器需要维护状态映射和本地播放策略；逻辑状态持续时间与本地动画片段长度可能不同，切换时表现为切断或保持末帧。
- 行为流程作者需要显式声明语义状态，既有动作定义也必须遵守同一语义边界。
- 状态目录需要由引擎与渲染资源共同维护；新增语义必须同步更新两侧映射，不能只依赖行为数据即时解释。
- 单成员只输出一个动作状态。多部位并行动画或同时存在的叠加视觉状态不在本决策范围内。

## 重新评估条件

- 动态技能步骤需要超出通用状态目录的逐技能或逐步骤视觉状态。
- 出现必须同时呈现的多个动作状态层，例如上半身施法与下半身移动。
- FSM 与 BT 无法继续通过互斥和中断规则消解状态选择，需要引入显式冲突裁决。
- 渲染器必须依据逻辑结束时间而不是下一状态切换来推进动画。
- 需要跨进程、跨设备或持久化消费成员状态帧。
