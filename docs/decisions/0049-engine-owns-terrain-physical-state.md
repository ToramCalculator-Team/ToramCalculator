# 0049 - 引擎拥有地形物理状态权威

- **状态**: Accepted
- **日期**: 2026-08-14
- **决策层**: 跨层（场景解析 / 引擎 / 地形生成 / 渲染）
- **相关代码**: `src/lib/terrain/`、`src/engine/core/World/`、`src/features/simulator/preview/resolveEngineScenario.ts`、`src/platform/terrain/`
- **相关 ADR**: Refines 0027；Depends on 0016

## 决策问题

程序化地形同时影响成员的物理位置和场景网格。系统需要决定由渲染层独立把逻辑平面位置投影到地形、由引擎拥有全部地形实现，还是让逻辑与渲染消费同一份确定性地形定义并保持单一物理权威。

## 决策驱动

- 成员世界位置必须只有一个权威来源，渲染层不能改写逻辑状态。
- 同一场景的碰撞高度与可见网格必须能够由相同输入重复生成。
- 引擎 Tick 内的地形查询必须同步且确定，不能依赖相机区块是否已生成。
- Babylon 网格、材质和相机附近区块生命周期不能进入逻辑引擎。
- 无逻辑引擎的静态预览仍需要显示在同一地形上。

## 候选方案

### A. 渲染层独立投影成员高度

- 优点：逻辑引擎继续只处理水平平面，地形接入范围较小。
- 缺点：渲染坐标与引擎状态分叉，相机、区域、碰撞和记录无法共享同一世界位置。

### B. 引擎拥有地形生成与渲染实现

- 优点：地形数据和成员位置集中在一个运行时中。
- 缺点：引擎需要依赖 Babylon、相机和网格生命周期，破坏计算与显示边界。

### C. 共享确定性地形定义，引擎拥有物理权威

- 优点：逻辑采样与渲染区块来自同一输入；引擎输出完整世界位置，渲染层只投影；网格生成仍可独立演化。
- 缺点：场景解析需要版本化地形定义，纯地形内核必须同时兼容引擎和 Worker。

## 决议

选择 C：**场景解析产出版本化、确定性的地形定义；逻辑引擎使用该定义计算成员物理状态并拥有完整世界位置权威，地形 Worker 和渲染器只生成与显示同源地形。**

- 地形定义与逻辑输入、静态世界资源属于同一份已解析场景，调用方不能分别采用隐式默认值。
- 纯地形内核只依赖地形定义和世界坐标，提供同步点采样与可独立重建的区块生成。
- 引擎在 Tick 内同步读取地面高度，计算成员的水平位置、垂直位置、落地和其他物理状态。
- 实时渲染实体直接消费引擎输出的完整位置，不重新采样地形，也不把显示位置写回逻辑投影。
- 地形 Worker 只负责可延迟的区块批量计算；相机附近区块是否就绪不得改变引擎 Tick 结果。
- 无引擎参与的静态预览可以使用同一纯地形内核做显示投影，但该投影不是实时运行事实。
- 模型资源必须把实体根归一化为逻辑接地点；模型自身原点差异由渲染资源内部的局部变换吸收。

## 代价

- 场景协议需要携带地形定义及版本，逻辑引擎和渲染 Worker 必须使用兼容的生成内核。
- 引擎点采样与渲染区块生成可能重复少量计算，以换取 Tick 不依赖异步区块生命周期。
- 跳跃、坡度和复杂碰撞需要在引擎世界模型中逐步完善，不能由渲染层临时修正。
- 非确定性地形修改需要新的权威状态与同步协议，不能继续只依赖种子重建。

## 重新评估条件

- 世界支持运行时可破坏、可编辑或依赖服务端流式下发的地形，种子和配置不能完整重建物理表面。
- 地形点采样成本超过 Tick 预算，必须改为预加载、版本化的碰撞区块。
- 引入独立物理 Worker，并由它取代引擎 Tick 成为成员物理位置权威。
