# 0050 - 实时状态的传输语义分类

- **状态**: Accepted
- **日期**: 2026-08-14
- **决策层**: 跨层（Session / 输入 / 引擎线程 / 渲染）
- **相关代码**: `src/features/simulator/session/`、`src/engine/core/thread/`、`src/platform/render/scene/input/`
- **相关 ADR**: Refines 0037、0040、0045；Depends on 0042

## 决策问题

实时控制输入和引擎世界状态需要跨越主线程、引擎 Worker 与渲染循环传递。系统需要决定：所有变化是否都走同一种传输形式（逐次消息），还是按数据的内在语义分成两条路径——只需要最新值的连续状态走 latest-state 通道，不可丢失的离散动作走事件队列。

## 决策驱动

- 高频连续状态（移动方向、世界位置）只需要最新完整值，过期中间值是噪声而不是信息。
- 技能、跳跃、目标选择等离散动作必须逐次处理，任何一次丢失都产生可见的游戏错误。
- 同一套传输机制无法同时满足「允许覆盖旧值」和「保证每次都被消费」两个相反的语义。
- CUI 和 SceneRuntime 不能持有可绕过 Session 调用引擎命令的能力。
- 没有实时控制或渲染消费者的执行路径不能承担 latest-state 通道的环境门槛和写入成本。

## 候选方案

### A. 所有输入和输出都使用逐次消息

- 优点：只有一种传输形式，调试路径直观。
- 缺点：连续状态会形成过期队列，高频世界状态需要重复克隆，消费者仍需自行丢弃旧值；语义上是错误的——「最新状态」不应该排队。

### B. 所有输入和输出都使用共享内存

- 优点：零复制，读写延迟最低。
- 缺点：离散动作没有「已被消费」的保证，技能输入可能被覆盖而丢失；无法表达「此事件必须被处理」的语义。

### C. 按语义分类：连续状态用 latest-state 通道，离散动作用事件队列

- 优点：每条路径的机制与数据语义匹配；连续状态天然允许跳帧，离散动作有排队与消费保证。
- 缺点：需要为两类数据分别定义窄能力和生命周期管理。

## 决议

选择 C：**连续状态使用 latest-state 语义的单槽通道，消费者只读最新值并允许跳过中间帧；不可丢失的离散动作进入事件队列，必须经过 Session 的阶段门控后串行消费。**

分类判据：
- **latest-state 通道**：消费者在任意时刻只需要当前值，两次读取之间若有多次写入，中间值可以丢弃而不影响正确性。适用对象：移动方向与强度、引擎成员世界位置/朝向。
- **离散事件队列**：每次写入都必须被消费一次且仅一次，丢失任何一次都产生可见错误。适用对象：技能触发、跳跃、目标选择、复活。

所有权与生命周期推论：
- Session 创建、附加和释放连续控制输入通道；SceneInputController 只获得写入最新移动状态的 sink，不持有 Engine Handle 能力。
- 技能、跳跃等离散动作必须作为 Session event 进入状态机，再由 Session 调用受限 Engine Handle。
- 实时世界状态投影由消费它的 Session 显式附加；通用 `loadScenario`、批量任务和无渲染预览不隐式创建该通道。
- 引擎输出当前完整渲染事实；渲染器只读，并在本地维护可丢弃的插值状态。

实现说明（可替换，不取代本 ADR）：
- 当前 latest-state 通道使用 SharedArrayBuffer + seqlock。布局、字段编码和具体 transport 属于版本化代码契约；只要 latest-state 语义、权威方向和 Session 所有权不变，可以替换为其他零复制机制。
- 共享内存不可用时，由申请对应实时能力的边界明确失败；通用引擎能力不惰性降级。
- 传送、硬校正和实体重建属于连续性中断；渲染器收到对应权威事实后必须丢弃旧平滑状态。
- 一次性视觉事件可以保留在命令流，但稳定运动状态不能同时由命令流和 latest-state 通道维护两份权威。

## 代价

- Session runtime 需要管理不进入可序列化业务上下文的线程附件和释放顺序。
- SharedArrayBuffer 实现要求实时功能运行在安全且跨源隔离的环境中。
- latest-state 通道不会保留中间值，任何必须逐次处理的语义都需要明确进入离散事件协议。
- 渲染器需要维护本地插值缓存，并在权威位置连续性中断时可靠地丢弃旧缓存。

## 重新评估条件

- 浏览器提供无需跨源隔离、同时满足零复制 latest-state 读写的新标准机制。
- 实测消息传输在目标频率和成员规模下满足预算，且共享内存环境门槛成为主要产品限制。
- 实时世界状态需要跨进程、跨设备或持久化消费，Session 内共享内存不再覆盖主要生命周期。
- 控制输入不再来自本地实时设备，而需要可确认、可重放的远程命令序列。
