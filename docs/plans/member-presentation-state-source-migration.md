# 成员渲染状态来源迁移计划

- **状态**: 未开始
- **日期**: 2026-09-29
- **前置决策**: 实施前新增取代 ADR 0053 的架构决策
- **相关决策**: ADR 0052、0053、0056

## 目标

移除独立的全局成员动作状态目录，让成员自身的静态 FSM 状态图和 active effect BT 共同提供渲染状态来源：

```text
成员 FSM 状态图
  -> 成员生命周期渲染状态

active effect BT 的 state 动作
  -> 技能流程渲染状态

Member.getPresentationState()
  -> 汇合为单一最终状态

Tick 提交边界
  -> 写入实时状态 SAB
```

状态机的 entry 不直接写 SAB。SAB 只在 Tick 提交边界接收 Member 已汇合的最终状态。

## 设计约束

1. 不再维护独立的全局 `MemberStateName` 状态目录作为 Player/Mob 的共同状态枚举。
2. Player 和 Mob 各自的 FSM 状态图是成员生命周期状态的权威来源，因此允许两者拥有不同的状态结构和状态集合。
3. FSM 状态图节点通过元数据标记是否具有 presentation state；未标记的纯流程控制节点不直接暴露给渲染层。
4. 渲染状态直接使用被标记节点的 FSM 状态路径，避免在 `resolveFsmState()` 中维护第二份名称映射。
5. active effect BT 的 `state` 动作继续用于技能流程状态；AI 行为树和 parallel BT 不得声明成员当前动作状态。
6. Member 提供统一的 `getPresentationState()`，负责处理 FSM 状态、active effect BT 状态、生命周期中断和同名状态重新进入。
7. 最终状态至少保留状态名、连续实例边界和逻辑开始时间，不能退化为只有一个字符串的 getter。
8. 渲染层只消费统一的最终状态输出，不读取 FSM 快照、不理解 BT 结构，也不复制状态优先级裁决。
9. 逻辑引擎不输出动画片段、播放倍率、动画进度或渲染完成事件；静态资源映射继续由渲染层负责。
10. 状态变化不得通过 FSM entry 直接写 SAB；状态生产和线程间传输保持独立。

## 前置治理

该方案改变 ADR 0053 中“状态目录与 FSM/BT 汇合”的长期边界，属于已发布架构决策的取代，而不是普通重构。实施前必须：

- 评估 FSM 状态路径是否足以作为跨引擎、跨渲染资源的稳定契约。
- 明确 FSM 节点元数据的静态来源、继承规则和缺失标记行为。
- 明确 BT `state` 动作产生的状态标识如何与 FSM 状态路径组合或并列。
- 评估 Player/Mob 不同状态图对静态渲染资源映射和兼容性的影响。
- 创建新的 ADR，声明 `Supersedes 0053`，并将 0053 标记为 `Superseded by <新编号>`；同步当前决策视图和历史目录。

## 实施阶段

### 阶段 1：状态图元数据契约

- [ ] 为 Player/Mob FSM 状态节点确定 presentation state 元数据表达方式。
- [ ] 确定状态路径规范、根节点是否包含成员类型或机器 ID，以及路径稳定性要求。
- [ ] 为纯控制状态、并行状态和没有 presentation 标记的父节点定义投影规则。
- [ ] 为状态图静态检查增加重复、缺失和不可投影状态诊断。
- [ ] 为渲染资源映射增加按实际成员状态路径校验的测试。

### 阶段 2：Member 状态汇合

- [ ] 新增统一的 presentation state 输出类型，放置在跨层状态契约的合适位置。
- [ ] 将 Member 当前 FSM 状态解析改为读取状态图元数据和运行时状态路径。
- [ ] 将 active effect BT 的 `state` 动作改为记录技能流程状态及其逻辑开始时间。
- [ ] 实现 `Member.getPresentationState()`，按成员生命周期裁决结果汇合 FSM 与 active effect BT。
- [ ] 保留同名状态的重新进入边界，使渲染器能重置对应表现。
- [ ] 覆盖 Player、Mob、技能阶段、状态中断、技能替换和恢复场景。

### 阶段 3：SAB 与渲染投影迁移

- [ ] 将实时状态写入器改为消费 `Member.getPresentationState()` 的最终结果。
- [ ] 删除 FSM entry 对 SAB、渲染对象或渲染资源的直接依赖。
- [ ] 保持 SAB 的 latest-state 提交语义和统一 Tick 提交边界。
- [ ] 将渲染资源映射从全局状态枚举迁移到实际状态路径契约。
- [ ] 验证状态切换、同名重入、跨 Tick 采样和状态缺失时的降级行为。

### 阶段 4：删除重复来源

- [ ] 删除全局 `MemberStateName` 状态目录及其仅为该目录服务的转换代码。
- [ ] 删除 Player/Mob 中手动维护的 FSM 状态到公共状态名映射。
- [ ] 删除渲染层对公共状态枚举的依赖。
- [ ] 更新 ADR、代码注释、测试和相关文档中的旧状态来源描述。
- [ ] 确认没有第二处独立维护 Player/Mob 生命周期状态名称的注册表或映射表。

## 验收标准

- Player 和 Mob 可以拥有不同的 FSM presentation state 集合，不需要修改共享全局状态枚举。
- 渲染状态能从当前 FSM 状态路径和 active effect BT 状态确定性重建。
- 同一 Tick 内的中间 FSM 转换不会直接泄露到 SAB；SAB 只提交 Tick 收尾的最终状态。
- FSM entry 不依赖 SAB 布局、Worker buffer 或渲染对象。
- 技能 BT 的状态声明不会绕过 FSM 的死亡、控制和中断裁决。
- 状态重新进入时，渲染层能通过实例边界识别并重置表现。
- 不存在被代码、类型或渲染资源继续依赖的全局 `MemberStateName` 目录。

## 风险与未决问题

- FSM 内部节点重命名会影响渲染资源映射；新 ADR 必须决定状态路径是否视为稳定外部契约，以及如何处理重命名兼容。
- active effect BT 的技能状态不是 FSM 状态路径，需要明确其命名空间和与 FSM 状态的组合关系。
- Mob 当前没有完整技能阶段 FSM，不能假设所有渲染状态都来自 FSM。
- 如果未来需要同时表现多个动作层，单一 `getPresentationState()` 可能不足，需要重新评估 ADR 的单状态边界。
