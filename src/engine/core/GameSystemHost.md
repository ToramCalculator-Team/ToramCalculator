# GameSystemHost

## 模块职责

游戏系统宿主承载游戏系统，为它提供运行所需的外部条件，并管理它与外部的交互。

1. **提供环境**：提供唯一时钟，并把控制器交来的输入读取端传给游戏系统。
2. **执行命令消息**：接收生命周期命令与 RPC，执行后回报结果并推送事件。
3. **接入观察者**：按消费者声明创建观察者组件，读取游戏系统的状态对象与事件源，写各自的输出。
4. **构造与销毁**：用场景或一份既有状态构造游戏系统，停止时销毁实例与环境资源。

## 理想结构

```typescript
class GameSystemHost<TTag, TSnapshot> {
  /** 唯一逻辑时钟。 */
  private readonly clock: PausableHostClock;

  /** 当前游戏系统。 */
  private gameSystem: GameSystem | null;

  /** 当前推进状态。 */
  private running: boolean;
}
```

```typescript
/**
 * 构造游戏系统
 *
 * 把宿主时钟、控制器提供的输入读取端与场景交给游戏系统工厂；初始化后按需恢复检查点。
 *
 * @param create 游戏层提供的构造函数，接收宿主时钟、输入读取端与场景
 * @param options 输入读取端、场景与可选检查点
 */
loadGame(create: GameSystemFactory<TTag, TSnapshot>, options: LoadGameOptions<TTag, TSnapshot>): void

/**
 * 启动时钟。时钟前进，游戏系统在到期时刻完成工作。
 */
start(): void

/**
 * 暂停游戏系统并停住逻辑时钟，系统停在当前已完成的时刻，输入采样随之停止。
 */
pause(): void

/** 恢复时钟前进。 */
resume(): void

/**
 * 把时钟拨到下一项工作的时刻并停住。
 *
 * @returns 推进后的逻辑时刻；没有已排定的工作时返回 null
 */
stepToNext(): SimulationTime | null

/** 销毁游戏系统、观察者与时钟。 */
stop(): void
```

场景与状态数据的校验放在构造函数内部，宿主把校验失败转成加载失败。

### 时钟

宿主持有唯一时钟，游戏系统经由它获得全部时间能力：

| 能力 | 用途 |
|---|---|
| 当前时刻 | 读取物理时间 |
| 一次唤醒 | 到达到期时刻时调用游戏系统 |
| 取消唤醒 | 撤销已安排的唤醒 |

时钟前进时，到期的唤醒按先后顺序触发。启动、暂停、恢复、单步、停止都是对时钟的操作；暂停即停住时钟，唤醒随之中止。

单步返回时，该时刻的工作不一定完成，但是 `getNextTime()` 应该已经前进到下一条；连续两次单步之间不需要确认机制。

遥测、调试视图与消息传输使用真实时间，与提供给游戏系统的时钟分开。

### 输入通道

控制器创建并持有输入邮箱，将读取端交给宿主；宿主装载游戏系统时把读取端传入，游戏系统内采集器的定时工作使用宿主时钟，因此暂停时停钟即可停止采样，恢复时随时钟恢复。

### 观察者

观察者是数据消费端的数据源：读取状态对象或事件源，按自己的频率产出数据，写自己的输出。

| 产出形状 | 说明 | 典型用途 |
|---|---|---|
| 输出缓冲 | 跨线程时写入自己的缓冲区，读取方按发布号取一致快照 | 渲染数据、调试界面数据 |
| 运行产出 | 在内存中累积，运行结束时整体移交 | 输入记录、状态历史 |

## 关键设计决策

### 1. 宿主只操作自己持有的对象

**设计理念**：运行环境与模拟逻辑分离，各自只维护自己的状态。

宿主通过时钟控制游戏系统的推进。宿主的运行期控制作用于时钟、系统实例或观察者句柄。

### 2. 运行与暂停只差时钟是否前进

**设计理念**：同一份机制承担多种运行形态。

生命周期收敛为时钟的两种取值，定时推进、暂停、单步与快进共用一条通道。

### 3. 观察者是数据消费端数据源

**设计理念**：数据的产出节奏由消费需求决定。

观察者按自己的频率读取状态对象或事件源。
