# GameSystemHost

## 模块职责

游戏系统宿主承载游戏系统，为它提供运行所需的外部条件，并管理它与外部的交互。

1. **提供环境**：提供输入输出端口和各种采集器环境，并把控制器交来的输入读取端传给游戏系统。
2. **执行命令消息**：接收生命周期命令与 RPC，执行后回报结果并推送事件。
3. **接入观察者**：按消费者声明创建观察者组件，读取游戏系统的状态对象与事件源，写各自的输出。
4. **构造与销毁**：用场景或一份既有状态构造游戏系统，停止时销毁实例与环境资源。

## 理想结构

```typescript
class GameSystemHost<TTag, TSnapshot> {
  /** 当前游戏系统。 */
  private gameSystem: GameSystem | null;

  /** 当前推进状态。 */
  private running: boolean;
}
```

```typescript
/**
 * 构造游戏系统
 *
 * 把平台能力、控制器提供的输入读取端与场景交给游戏系统工厂；初始化后按需恢复检查点。
 *
 * @param create 游戏层提供的构造函数，接收输入读取端与场景
 * @param options 输入读取端、场景与可选检查点
 */
loadGame(create: GameSystemFactory<TTag, TSnapshot>, options: LoadGameOptions<TTag, TSnapshot>): void

/** 转发启动命令。游戏系统开始自己的调度循环。 */
start(): void

/**
 * 转发暂停命令。游戏系统停住自己的调度，系统停在当前已完成的时刻，输入采样随之停止。
 */
pause(): void

/** 转发恢复命令。从暂停点继续。 */
resume(): void

/**
 * 转发单步命令。游戏系统把时钟拨到下一项工作的时刻并停住。
 *
 * @returns 推进后的逻辑时刻；没有已排定的工作时返回 null
 */
stepToNext(): SimulationTime | null

/** 销毁游戏系统、观察者与平台资源。 */
stop(): void
```

场景与状态数据的校验放在构造函数内部，宿主把校验失败转成加载失败。

### 输入通道

控制器创建并持有输入邮箱，将读取端交给宿主；宿主装载游戏系统时把读取端传入，根据配置决定输入采集频率。
### 观察者

观察者是数据消费端的数据源：读取状态对象或事件源，按自己的频率产出数据，写自己的输出。

| 产出形状 | 说明 | 典型用途 |
|---|---|---|
| 输出缓冲 | 跨线程时写入自己的缓冲区，读取方按发布号取一致快照 | 渲染数据、调试界面数据 |
| 运行产出 | 在内存中累积，运行结束时整体移交 | 输入记录、状态历史 |

## 关键设计决策

### 1. 观察者是数据消费端数据源

**设计理念**：数据的产出节奏由消费需求决定。

观察者按自己的频率读取状态对象或事件源。
