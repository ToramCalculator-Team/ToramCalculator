# EventBus

> 本模块遵循 [ADR 0059](../../../../docs/decisions/0059-facts-published-on-subscription-driven-single-bus.md) 的当前修订。本文描述每个 GameReactor 持有的内部事件总线。

## 模块职责

`EventBus` 在单个游戏反应器作用域内发布已发生的领域事实，并将事实交给匹配的订阅者。

1. 发布事件及其不可变负载。
2. 按事件名称匹配订阅，并把事件交付给订阅者。
3. 将事件同步分发给内部逻辑订阅者及已注册的外部观察订阅者。
4. 提供可取消的订阅句柄，供能力实例、动态 GameReactor 与消费者输出实例按生命周期清理订阅。

事件总线机制由引擎提供；事件词汇、事实成立时机和负载形状由游戏规则定义。订阅由逻辑能力或消费者配置声明。总线不管理逻辑时间、不调度未来操作、不保存已发布事件，也不直接执行 BT。

## 理想结构

```typescript
interface DomainEvent<TPayload = unknown> {
  readonly name: string;
  readonly payload: TPayload;
}

interface EventBus {
  subscribe<TPayload>(
    name: string,
    listener: (event: DomainEvent<TPayload>) => void,
  ): () => void;

  publish<TPayload>(event: DomainEvent<TPayload>): void;
}
```

每个 `GameReactor` 持有自己的事件总线。执行过程确认事实后调用 `publish(event)`；总线在当前调用中按事件名同步调用匹配的订阅者。发布结束后总线不保留事件，因此未匹配订阅的事件自然消散，之后建立的订阅也不会收到历史事件。

`BTRuntime` 管理 BT 实例的内部订阅。外部事件输出过滤器作为独立订阅者注册到相关 GameReactor 的 EventBus；它只筛选并暂存订阅事件，不参与模拟逻辑。能力实例销毁或 GameReactor 结束时取消对应订阅。发布与订阅使用游戏包提供的事件目录校验名称和负载。

## 事件目录

游戏包提供事件名称和负载 schema。EventBus 按事件名称分派，发布与订阅入口对照所属游戏包的目录校验负载。内部事件目录不隐含对外输出声明。

## 关键设计决策

### 1. 事件总线按游戏反应器隔离

**设计理念**：事实的可见范围与其领域归属一致。

每个游戏反应器持有自己的总线实例。游戏规则可以通过负载表达目标身份，但发布和订阅不会隐式跨越反应器边界。外部观察组件可在 GameSystem 装配与生命周期管理下，显式订阅多个 GameReactor。

### 2. 总线分发事实，订阅者同步响应

**设计理念**：组件内事实通知不构造网络数据依赖。

总线在当前调用中把事件交给订阅者；BT 订阅者由 `BTRuntime` 推进对应实例。需要跨 tag 执行的未来操作由 Reactor `Action` 调度，到期后执行并按需发布事实。

### 3. 总线是同步分发，不是事件存储

**设计理念**：事件的生命周期由一次发布和当时存在的订阅决定。

事件只在发布调用期间交付。没有匹配订阅者时不排队、不覆盖“上一条事件”，也不产生历史记录。需要留存事件的订阅者负责自己的缓冲与容量策略。

### 4. 外部观察是显式订阅者

**设计理念**：观察配置不决定事实是否发生，也不决定内部响应。

外部事件过滤器只有在消费者声明事件输出时才创建，并显式订阅目标 GameReactor 的 EventBus。过滤器筛选匹配事件并暂存给 SAB 写入器；未配置外部事件观察时，不创建这类订阅。
