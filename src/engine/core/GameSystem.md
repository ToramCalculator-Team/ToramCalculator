# GameSystem

## 模块职责

GameSystem 是复刻自实际游戏的受控系统，按既定规则响应输入与时间。

1. **受控状态**：保存系统状态，以场景或一份既有状态作为初始状态。
2. **每步完成后发布状态**：维护统一状态对象，每一步执行完毕后更新，供同一线程内的读取方读取。
3. **报告下一步时刻**：给出已完成到的逻辑时刻与下一项工作的逻辑时刻。
4. **自有调度**：持有自己的调度时钟与调度循环，把宿主转发的生命周期命令映射为调度操作。

## 理想结构

```typescript
interface GameSystem {
  /**
   * 已完成到的逻辑时刻。
   *
   * @returns 当前逻辑时刻
   */
  getCurrentTime(): SimulationTime;

  /**
   * 下一项工作的逻辑时刻。
   *
   * @returns 下一项工作的时刻；没有已排定的工作时返回 null
   */
  getNextTime(): SimulationTime | null;

  /** 统一状态对象，每步执行完毕后更新。 */
  readonly state: SystemState;

  /** 启动调度循环。 */
  start(): void;

  /** 暂停调度循环，保留状态与待处理工作。 */
  pause(): void;

  /** 从暂停点继续。 */
  resume(): void;

  /** 推进一个逻辑时刻；只应在暂停时调用。 */
  stepToNext(): SimulationTime | null;

  /** 销毁实例并停止调度。 */
  dispose(): void;
}
```

### 状态对象

系统只维护一份状态，每一步执行完毕后整体更新为最新完成时刻的状态。以便外部读取状态信息。

### 时间

游戏系统自己持有调度时钟与调度循环；时间读取、唤醒安排与取消都在实现内部完成。宿主只转发启动、暂停、恢复、单步与停止命令。调度时钟的归属决策见 [ADR 0062](../../../docs/decisions/0062-host-does-not-own-scheduling-clock.md)。

暂停语义由契约保证：暂停后真实时间流逝不改变已完成逻辑时刻、不触发任何工作；恢复从暂停点继续，不补算暂停期间的真实时间。

## 关键设计决策

### 1. 状态对象是唯一读取面

**设计理念**：单一事实源优于为每个消费者维护一份产出。

所有读取方从同一份状态读取，差异由读取方投影得出。

### 2. 调度与时间能力由实现持有

**设计理念**：调度是模拟实现的一部分，不是外部环境。

系统读取时刻、安排唤醒与取消唤醒都经过自己的调度时钟；宿主只提供平台能力与生命周期命令，不参与推进节奏。

### 3. 暂停语义由契约承担

**设计理念**：生命周期命令与实现解耦后，暂停与恢复必须由可验证的语义保证。

暂停、恢复、单步在契约层面定义结果，不规定实现方式；实现违约由契约测试暴露，而不是由宿主冻结环境兜底。
