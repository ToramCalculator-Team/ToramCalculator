# InputSampler

## 模块职责

1. **读取输入快照**：按采样周期从输入缓冲读取一份完整快照，发布号不变时不产生事件。
2. **状态零阶保持**：把方向、步态、强度等连续量写入网络内持久的输入状态。
3. **命令逐条入 tag**：把离散命令按发布顺序调度为当前 tag 的后续微步，保证不丢失、不合并。
4. **确定输入分辨率**：采样周期是控制器输入的可观测分辨率，也是输入延迟的上界。
5. **切换输入源**：实时模式读共享缓冲，回放模式读输入日志，网络路径不变。
6. **暂停期间不采样**：采样定时器随暂停停止，恢复时不补采暂停期间的输入。

InputSampler 不解析业务语义，不推进模拟，不写输出缓冲。

## 关键设计决策

### 1. 采样器在网络内

**设计理念**：产生 tag 的适配器必须在网络内，时间基准才唯一。

采样器读取外部输入后要产生事件；如果它在网络外，只能通过物理动作注入，tag 就来自平台时钟，重放失效。

### 2. 采样周期就是输入分辨率

**设计理念**：输入通道只能观察控制器发布过的值。

控制器按自己的频率发布，采样器高于该频率不会增加信息，低于该频率会丢失命令。周期取控制器发布周期或它的整数倍，具体值由输入延迟预算决定。

### 3. 状态与命令分开

**设计理念**：连续量可以合并，离散事实不能合并。

方向、步态、强度取最新值；按键、技能、闪避等命令逐条消费。一个采样周期内出现多条命令时，按发布顺序调度到同一 tag 的递增微步，不能只保留最后一条。

### 4. 发布号去重

**设计理念**：没有变化的输入不产生事件。

发布号未变化时，采样只做零阶保持，不写端口、不调度动作。网络不会因为输入采样而空转。

### 5. 输入源可替换

**设计理念**：实时与回放共用同一条网络路径。

采样器只依赖输入源接口。实时源读共享缓冲，回放源按 tag 读日志；网络、成员与采集器不需要知道当前是哪种模式。

### 6. 暂停不接受输入

**设计理念**：暂停是决策与观察的时机，不是绕过操作时限的手段。

暂停期间控制器不向输入缓冲写入，采样器定时器不触发，恢复后从暂停时的输入状态继续。控制器本身不受影响，它照常采样自己的设备并维护内部状态。命令区因此不存在跨暂停的积压，容量只需覆盖正常运行时的突发。
