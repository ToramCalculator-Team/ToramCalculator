# 通信协议导读

> 本文是线程通信的人工导读。可执行契约以 `src/engine/core/thread/protocol.ts`、
> `src/engine/core/thread/worldStateBuffer.ts` 和对应测试为准。

## 通道分类

模拟器按数据语义使用四类通道，不把它们合并成通用消息总线：

| 通道 | 方向 | 语义 | 当前载体 | 生命周期所有者 |
|---|---|---|---|---|
| 命令 / 查询 | Main -> Worker -> Main | 每次请求必须得到一次成功或失败结果 | 类型化 RPC | `EngineWorkerClient` |
| 离散推送 | Worker -> Main | 每个变化都需要被观察或按批处理 | `WorkerSystemMessage` | Worker / 订阅方 |
| 最新连续状态 | Worker -> Main | 只读最新完整值，允许跳过中间提交 | 单槽 SAB + seqlock | `SimulatorSession` |
| 完整 Tick 历史 | Worker -> Main | 保存每个 Tick，供运行分析读取 | 分段历史 SAB | 运行产出收集器 |

控制器的连续移动输入使用独立 latest-state SAB；技能、跳跃和目标选择仍是必须逐次处理的 Session 意图。

## RPC

`EngineRPCSchema` 是请求类型的唯一索引，`EngineRPCDataSchemaByType` 为每个请求定义对应成功结果。当前主要请求包括：

- 成员查询、技能列表、调试视图订阅和取消订阅。
- 运行配置、成员配置更新、模拟任务与运行产出移交。
- 控制器输入 SAB 的附加和解除。
- 实时世界状态布局查询、SAB 附加和解除。

引擎生命周期命令使用带 `correlationId` 的双端状态机协议。Worker 只有在权威执行端完成副作用后才返回结果，主线程不能仅根据请求发出推断生命周期已改变。

## 离散推送

`PushMessageType` 当前包含：

| 顶层类型 | 用途 |
|---|---|
| `engine_lifecycle_snapshot` | Worker 权威生命周期只读投影 |
| `engine_telemetry` | Tick、逻辑时间、TPS 和成员数等轻量遥测 |
| `domain_event_batch` | 成员领域事件面向控制器和 UI 的批投影 |
| `debug_view_frame` | 显式订阅后产生的调试视图帧 |
| `system_event` | Worker 就绪和受限的系统级通知 |

连续成员状态、区域状态和动画状态不进入离散推送。

## 实时世界状态

实时世界状态遵循两阶段附件协议：

1. 场景成员装配完成后，主线程通过 `get_world_state_layout` 取得版本化布局。
2. Session 按布局创建 SAB，再通过 `attach_world_state_buffer` 交给 Worker。
3. Worker 附加后立即写入一个完整提交，之后在每个 Tick 收尾统一提交成员、属性、modifier 来源链、动画和区域。
4. UI 调度器与渲染帧各自读取最新稳定提交，可以跳过中间提交，不能跨提交逐表拼接。
5. Session 结束、切换或卸载时先停止主线程调度，再解除 Worker writer 和 reader。

静态模型、外观和动画映射由渲染器的 `VisualProfileRegistry` 持有。SAB 只保存稳定 `visualProfileId`，不保存资源定义。

## 约束

- Worker 是实时世界状态唯一写入者；UI 和渲染器只读。
- 所有实时表由同一个提交版本保护。
- SAB 布局版本、容量、字节长度或目录 offset 不一致时，附件必须失败。
- 实时成员槽和区域槽按 ID 复用，复用时递增 generation；消费者必须丢弃旧插值和动画缓存。
- modifier 和区域超出协商容量时必须返回稳定诊断，不能覆盖现有槽位。
- 普通批处理和没有实时消费者的执行不隐式创建实时状态 SAB。

相关架构理由见 ADR 0040、0044、0050 和 0052。
