一、生效范围 EffectRange

技能发生时，逻辑层首先确定的是技能的生效范围，而不是区域实体。

生效范围是一次技能效果使用的空间值，负责描述：

- 在什么位置进行判定。
- 使用什么形状进行判定。
- 形状的尺寸是多少。
- 使用哪个方向或朝向。
- 以施法者、目标还是锁定位置作为空间锚点。
- 是否包含区域生成所需的空间运动描述。

瞬时攻击使用生效范围执行一次查询，然后丢弃生效范围。持续攻击先确定生效范围，再根据攻击节点的语义决定是否生成持续区域。
生效范围是瞬时查询和持续区域查询共同使用的空间定义，但它们不是同一个运行时对象。

二、区域 Area

区域是模拟层中持续存在的逻辑空间对象。它负责在多个逻辑时刻继续进行范围判定，并在满足条件时派发领域效果。

区域存在的必要条件是：

> 技能生效后，世界是否仍然需要在后续逻辑时刻维护这个空间对象。

区域应包含以下领域事实：

```text
Area
├─ id / sourceId / sourceSkillId
├─ effectRange：区域当前使用的形状、尺寸和空间锚点
├─ pose：当前的位置和朝向
├─ trajectory?：区域的空间运动
├─ lifecycle：开始时间、持续时间或移动结束条件
├─ hitPolicy：每个目标的重复命中间隔
└─ effectPayload：命中后派发的领域效果数据
```

区域只表示持续存在的逻辑对象。
如果多段攻击只对已经锁定的目标按时间派发后续段数，并不需要后续重新查询空间范围，则仍然可以属于瞬时攻击执行流程，不必创建 Area。只有后续逻辑时刻仍需要根据当前位置重新检索范围成员时，才需要持续 Area。

三、区域生成器

区域生成不是一种新的攻击类型，而是持续攻击节点可以调用的底层能力。

他的职责是：

1. 接收已经解析好的持续伤害效果定义。
2. 创建一个持续存在的 DamageArea 实例。

攻击节点的职责保持清晰：

```text
singleAttack / rangeAttack / surroundingsAttack / lineAttack
  → 解析生效范围
  → 执行一次范围查询
  → 派发伤害
  → 不创建 Area

moveAttack / groundLineAttack / bulletAttack
  → 解析生效范围和运动描述
  → createDamageArea

groundAttack / meteorAttack / explosionAttack / attractionAttack
  → 解析固定生效范围和持续规则
  → createDamageArea
```

攻击节点仍然直接表达单体、范围、周围、冲撞、直线、贴地、子弹和持续区域等领域类型；是否调用区域生成器由具体攻击节点的持续性决定。

四、轨迹 Trajectory

轨迹是区域的空间运动描述，是附属于区域的值。

轨迹只回答一个问题：

> 给定区域的开始时间和当前模拟时间，区域现在位于哪里。

轨迹可以包含：

- 起点和终点。
- 方向和最大距离。
- 路径几何，例如线段、射线、弧线或其他曲线。
- 移动速度。
- 求值所需的施法者或目标锚点。

没有空间运动的区域不带轨迹。

移动区域的结束条件可以由轨迹长度和移动速度推导。静止持续区域的结束条件由 Area 自身的生命周期决定。轨迹结束后，区域是否立即移除由区域生命周期和攻击语义决定。

五、技能范围与渲染边界

技能行为树按逻辑 Tick 执行。条件、目标和动态参数可能在攻击节点真正执行时才能确定，逻辑层不能为了渲染预警提前执行或复制行为树控制流。

因此，当前实时状态协议不提供技能生效前的范围预警数据：

- 不在成员运行时保存待生效攻击组或效果节点清单。
- 不把行为树节点、未执行分支或预测范围写入 SAB。
- 不提前锁定仍应动态跟随的 Member 目标。
- 渲染层不解析 MDSL，也不执行 selector、condition 或攻击参数表达式。

攻击节点真正执行时才解析 EffectRange。瞬时攻击立即使用范围查询并丢弃；持续攻击创建 Area，Area 的逻辑状态随后写入 SAB，供渲染层重建已经存在的区域视觉。

六、不同攻击类型的逻辑与 Area 视觉

| 攻击类型 | 生效范围 | 轨迹 | 生效后的逻辑处理 | Area 视觉 |
|---|---|---|---|---|
| 单体伤害 | 锁定目标的点范围 | 无 | 生效时对目标执行一次判定；多段锁定伤害按攻击时间轴派发 | 不创建 Area |
| 范围伤害 | 目标位置的圆形范围 | 无 | 生效时查询一次 | 不创建 Area |
| 周围伤害 | 施法者位置的圆形范围 | 无 | 生效时查询一次 | 不创建 Area |
| 冲撞伤害 | 随移动对象变化的圆形范围 | 有 | 通过 `createDamageArea` 持续更新并查询 | 固定位置矩形路径效果，以及随施法者移动的圆形范围效果 |
| 直线伤害 | 施法者到目标方向的矩形范围 | 无 | 生效时查询一次 | 不创建 Area |
| 贴地伤害 | 沿路径移动的配置形状 | 有 | 通过 `createDamageArea` 持续更新并查询 | 沿轨迹绘制线条，并绘制当前判定范围 |
| 子弹伤害 | 沿路径移动的圆形或配置形状 | 有 | 通过 `createDamageArea` 持续更新并查询 | 绘制随轨迹移动的动态判定范围 |
| 地面伤害 | 固定位置的圆形或矩形范围 | 无 | 通过 `createDamageArea` 在持续时间内周期查询 | Area 活动期间持续绘制区域 |
| 陨石伤害 | 技能定义的落点范围 | 通常无 | 持续效果通过 `createDamageArea`；纯瞬时落点效果执行一次查询 | 持续 Area 活动期间绘制区域 |
| 爆炸伤害 | 固定位置的圆形或矩形范围 | 无 | 通过 `createDamageArea` 周期查询 | Area 活动期间持续绘制区域 |
| 吸引伤害 | 固定位置的圆形或矩形范围 | 无 | 通过 `createDamageArea` 周期查询 | Area 活动期间持续绘制区域 |

“有轨迹”不等于统一绘制轨迹线。轨迹是逻辑空间事实，具体是否显示路径由对应 Area 视觉投影规则决定：冲撞可以投影为固定矩形路径，贴地可以投影为线条，子弹可以只使用轨迹更新动态范围而不额外绘制路径线。

七、执行和渲染数据流

```text
攻击节点真正执行
  → 解析 EffectRange 和必要的轨迹事实
  ├─ 瞬时攻击：查询一次成员并派发伤害
  └─ 持续攻击：调用 createDamageArea 注册 Area

持续 Area 运行期间
  → AreaSystem 更新位置和生命周期
  → AreaSystem 按范围检索成员并维护每目标伤害时间轴
  → Area 状态写入 SAB
  → AreaRenderer 绘制区域视觉
```

这里的单向关系必须保持：

- 逻辑层产生 Area 状态。
- SAB 传递可重建的逻辑事实，不传递视觉命令。
- Area 渲染器只理解 Area 状态，并在 Area 活动期间绘制区域。
- Area 轨迹不成为实体，视觉图元不成为 Area。

八、已确认的攻击节点约束

行为树继续使用已经准确定义的具体攻击节点：

```text
singleAttack
rangeAttack
surroundingsAttack
moveAttack
lineAttack
groundLineAttack
bulletAttack
groundAttack
meteorAttack
explosionAttack
attractionAttack
```

这些节点负责表达不同的攻击语义，并负责确定自己的生效范围。它们可以共用范围解析、伤害载荷构造和 `createDamageArea` 等底层能力，但不能被一个泛化的 `areaAttack` 替代。
