# 引擎架构设计

## 定位

引擎把一组反应器组织成可推进的网络，管理时间、输入、输出、检查点与运行记录。引擎只描述通用机制；成员、区域、世界等游戏概念由游戏层通过插件提供。

## 运行形态

| 形态 | 驱动 | 采集 |
|---|---|---|
| 实时模拟 | clocked，逻辑时间追赶物理时间 | 按消费端配置 |
| 快速流程模拟 | unclocked，尽快排空事件队列 | 通常关闭，用运行记录 |
| 预览模拟 | unclocked 或单步 | 按预览字段 |

约束：实时模拟至少 12 帧/秒，理想 60 帧/秒；受模拟反应器 2~96 个；快速流程模拟至少 5 分钟（18000 帧），理想 108000 帧。这里的“帧”指逻辑时间的一次推进段，不是固定步长。

## 时间模型

- 唯一时间轴是 tag：逻辑时间加微步。
- 时间由事件推进：事件队列非空时跳到队首 tag；队列空时等待物理时间或外部事件。
- 没有全局固定步长，没有帧序号，没有帧循环。
- 事件源：输入采样、端口级联、动作调度、定时器、模拟结束。
- 微步只用于同一逻辑时间内的因果先后；同一 tag 内的先后优先用端口依赖表达。
- 物理时钟只用于两处：调度器决定睡眠时长，采集器决定自己的采样节奏。
- 输入从输入端口进入并绑定当前 tag。网络内不使用物理动作；含物理动作的运行无法在同一 tag 序列上复现。

## 分层与数据流

```
控制面（消息）
  │ 生命周期命令、结果、诊断
  ▼
GameEngine（宿主）
  │ 生命周期、线程边界、SAB、检查点序列化
  ▼
GameSystem（当前 ReactorGameSystem extends App）
  │ 网络根、tag 推进、暂停/恢复、状态捕获
  ├── 游戏层网络根
  ├── InputSampler（网络内 reactor）◀── 输入缓冲
  ├── OutputCollector[]（网络外、周期采样）──▶ 输出缓冲 × N
  └── EventOutputFilter[]（网络外、事件订阅）──▶ 事件输出缓冲 × N
```

数据流单向：控制面进入 GameEngine，GameEngine 加载 GameSystem；输入经 InputSampler 进入网络；网络状态经参数端口发布，由 OutputCollector 周期采集；GameReactor 的 EventBus 同步分发事实，消费者配置的 EventOutputFilter 筛选并输出订阅事件；运行记录与检查点从 GameSystem 读取。

## 引擎与游戏层的边界

| 归属 | 内容 |
|---|---|
| 引擎 | 反应器运行时适配、tag 与微步、输入采样、输出采集、属性求值、计算管线、行为树运行时、Reactor 内 EventBus、xstate 运行时能力、检查点、运行记录、线程协议 |
| 游戏层 | 网络根、世界、成员与区域、xstate 状态机定义、意图与效果声明、行为树定义、属性 Schema、计算管线定义、输入命令语义、采集字段选择 |

游戏层提供 `GameSystem` 实现。当前的 `ReactorGameSystem` 建立网络根，并按消费者输出配置创建参数采集器和事件输出过滤器。游戏包的 `GameReactor` 组合 FSM actor、BTRuntime、AttributeContainer、EventBus 与 PipelineRuntime 等能力；实体按配置选择所需能力。引擎不引用成员、区域、世界等类型。

## 逻辑建模

引擎用 xstate v5 作为第一版状态机运行时，用 mistreevous 作为行为流程运行时。

- 状态机描述互斥状态与转移；行为流程描述状态内部的行为序列。
- FSM actor 是 GameReactor 内部组件，接收 EventBus 事件并提交意图；不通过端口接入。
- 状态机动作只提交意图：启动/停止流程、产生效果、调度定时器。GameReactor 负责分派。
- 行为流程是状态的活动：进入状态时启动，退出时停止；流程完成以事件回到状态机。
- 类型从机器定义推导：事件联合、上下文、快照、状态值；效果联合单独声明。
- 内置规则用代码生成的静态类型；玩家规则用运行期 schema 校验。两者共用同一份 xstate 定义格式。
- `invoke`/`spawn`/外部 `send` 禁用；`after` 编译成 `Action`；actor 只做同步状态容器。

## 输入边界

- 一个输入缓冲，控制侧是唯一写者，用发布号与重试读保证快照完整。
- 槽位分状态区与命令区：方向、步态、强度属于状态；按键、技能、闪避属于命令。
- 输入采样器在网络内，周期等于输入分辨率。它读取快照后，把状态写入连续量出口，把命令逐条调度到当前 tag 的后续微步。
- 发布号未变化时不产生事件；一个采样周期内出现多条命令时，按发布顺序逐条消费，不合并成最后一条。
- 输入只在 tag 边界生效。一个 tag 开始后，它的输入快照与反应集合固定，tag 内不再改变。

## 输出边界

- 每个采集器一个输出缓冲，一个采集器一个提交号。不同采集频率不共用提交号。
- 采集器在网络外，按自己的周期在 tag 完成边界读取参数视图，求值后写入自己的缓冲。
- 连续量允许读取方跳过中间提交，只取最新值；离散事实必须逐次消费；容量不足时显形失败，不静默覆盖。
- OutputCollector 按周期采集连续参数；EventOutputFilter 按事件订阅筛选离散事实。两者都不推进模拟，改变外部输出配置不改变模拟状态。

## 确定性与重放

- 网络内没有物理动作。输入、定时器、动作都绑定 tag，tag 序列由程序定义。
- 实时模式的非确定性只收敛在输入采样值上。输入日志记录 `(tag, 发布号, 快照)`。
- 回放等于同一场景、同一检查点、同一输入日志、unclocked 驱动。采样器从日志取值，网络与采集器不需要知道当前是实时还是回放。
- 同一随机种子、同一输入日志下，两次运行的记录逐 tag 相同。

## 检查点

检查点保存当前 tag、网络各节点的状态、事件队列中的未来事件，以及输入采样器的发布号。buff 到期、技能延迟、行为树等待都属于未来事件，只保存当前状态会让恢复后的时间线断裂。

采集器的输出缓冲、呈现帧与诊断计数是派生数据，不进入检查点；恢复后由网络重新发布。

## 与旧设计的差异

- 删除帧循环、帧序号、固定步长与全局逻辑频率。时间由 tag 承载，推进由事件队列决定。
- GameReactor 内已发生的领域事实由所属 Reactor 的 EventBus 同步分发且不存储；外部 EventOutputFilter 按消费者订阅筛选并输出匹配事件。连续网络参数由 OutputCollector 周期采样。需要进入网络的输入与输出由 Reaction 和端口表达；跨 tag 未来操作由 Reactor Action 调度。
- 成员、区域、世界等游戏概念从引擎文档移出，由游戏层提供 `GameSystem` 实现（当前是 `ReactorGameSystem`）来构建网络根与采集器。
- 状态机不作为 Reactor，而是实体反应器内部的 xstate 机器；状态内部的行为流程作为状态活动启动和停止。
- 不再有独立的装配接口与运行时适配层；装配与运行控制都在 `GameSystem` 实现内。
- 输出从“每帧提交一个端口”改为“每个采集器一个缓冲，按自己的周期提交”。输入从“每帧读一次”改为“采样 tag 上读一次”。

## 验收基线

1. 一个按定时器推进的反应器在不同周期下的位移一致。
2. 分段切换点是精确 tag；采集端外推误差不超过一个输入周期。
3. 不配置采集器时，模拟结果与配置采集器时逐 tag 一致。
4. 输入发布号不变时不产生事件；多条命令逐条消费，不丢失。
5. 同一随机种子与输入日志下，两次运行逐 tag 相同。
6. 96 个反应器实时运行时达到 12 帧/秒下限。
7. 同一内部事件序列下，GameReactor 所持 xstate actor 的状态、意图顺序、定时器与检查点恢复一致。
8. 暂停期间不推进 tag；恢复后 tag 序列与不暂停一致；检查点在新实例恢复后逐 tag 一致。
9. `GameSystem` 接口不引用 `App`、`Tag` 或 ECS 组件；`ReactorGameSystem` 通过同一组用例。
