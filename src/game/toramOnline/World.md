# World

## 模块职责

1. **成员与区域管理**：成员生命周期、状态与行为；瞬时伤害与持续区域的计算与应用。
2. **端口拓扑**：按数据依赖把成员、区域与子系统接成反应器网络，网络在装配期定型。
3. **输入应用**：按输入端口的目标身份标记把控制器意图施加到成员，无意图的成员回退到自身 AI 采样。
4. **时间语义**：把连续量表达为可外推的参数，把离散变化表达为 tag 上的事件。
5. **空间与地形**：成员空间查询、范围查询，以及地形高度投影。
6. **确定性随机与表达式求值**：为规则层提供可检查点的随机数与表达式计算能力。

World 不持有调度器、不持有对外缓冲、不控制生命周期。

### 时间语义

连续量与离散量分三类处理：

| 类别 | 表达 | 说明 |
|---|---|---|
| 时长与区间 | 两个 tag 上的事件：施加与过期 | buff 持续、冷却 |
| 物理与运动 | 参数发布 + 采集器外推 | 位置不在网络上逐帧更新 |
| 控制器输入 | 区间内零阶保持 | 异步到达，绑到 tag |

运动与属性的连续量以参数形式发布：分段起点、起点值、变化速率、分段零点时刻。参数只在分段切换时重发，不随推进逐帧重写。

**分段切换必须落在精确的 tag 上。** 切换时刻如果能解析求出，就用 `Action.schedule` 调度到该时刻；只有无法预知的切换（碰撞、输入引发）才允许滞后一个输入周期。切换时刻不是 tag 时，参数会拖到下一个 tag 才发布，采集端在那个区间内只能沿用旧参数外推，产生可见误差。

属性的时间相关修饰是惰性求值：修饰保存函数与生效区间，求值时代入当前 tag。它不累积误差，因为值只取决于 tag。

### 端口与发布

端口承担两类职责：

| 职责 | 表达 | 替换的旧机制 |
|---|---|---|
| 内部派发 | 端口级联，构造期静态接线 | 事件总线 |
| 对外发布 | 参数端口 + 采集器读取 | 逐 Tick 汇总后交引擎 |

端口值只在写入的那个 tag 上可见，跨 tag 不可读。需要跨 tag 持续可见的连续量由参数端口发布，采集器读参数并用状态方程外推；需要离散通知的由动作端口发布。

同一 tag 内多个反应依次写端口时，写入方可能读到半更新的组合。需要原子读取一组值的场合，把读取放在下一微步。

---

### 结算

结算不再是一个独立的阶段，而是同一 tag 上的一组反应。

同 tag 内的链式反应（伤害 → 死亡 → 复活 → 再次受伤）由微步推进完成：每个微步推进一次因果链，直到不再产生新工作。微步是 tag 的一部分，因此链式反应共享同一时刻，与顺序轴的定义一致。

微步的使用应当稀缺：同一 tag 内的先后优先用端口依赖表达，微步只用于真正需要区分因果的场合。

## 关键设计决策

### 1. 网络由数据依赖决定形状

**设计理念**：网络形状描述的是模块之间的固定关系，装配期确定一次即可，运行期不再推导。

成员之间的相互影响通过端口接线表达，接线在装配期完成。运行期没有接线变更，因此不需要在运行期做类型推导与重新校验；规则变更走重新加载。

### 2. 成员是一个反应器，不是一张状态机一个反应器

**设计理念**：反应器数量应当等于受模拟对象的数量，而不是对象数量乘以逻辑数量。

每个成员只有一个反应器，其反应函数体内调用库层的纯函数解释器推进状态机与行为树。时间基准由反应的 tag 提供，状态机与行为树层完全不感知调度，因而可以脱离网络单独测试。

### 3. 端口定长

**设计理念**：端口按对象类别保持同一形状，才能批量构造。

端口不按每张状态机各推一套，否则 `Bank` 无法按同一形状批量构造成员。类型多样性放在判别联合的成员里，联合的成员由节点实现的能力面声明在装配期静态算出。

### 4. 连续量发布参数，采集器外推

**设计理念**：状态方程只应有一份实现，且它属于引擎。

网络发布运动与属性的分段参数，不发布逐帧求值后的位置与数值。采集器读参数、按自己的频率代入状态方程求值、写输出缓冲。消费端只读结果，不持有求值代码。

这样呈现频率与推进频率相互独立，且求值公式不外泄到消费端。

### 5. 分段切换是事件

**设计理念**：参数的有效区间由事件界定，不由采样时刻界定。

参数在某个 tag 上发布后保持有效，直到下一个 tag 上发布新参数。若切换时刻不是 tag，参数就晚于事实生效，采集端在区间内用旧参数外推。因此能解析求出的切换时刻都要调度成 tag。

### 6. 空间索引不进网络

**设计理念**：变成反应器只为每次查询开端口往返，没有收益。

空间索引是被动 pull 式数据结构，由 World 直接持有。它需要遵守的约束只有一条：索引写入与读取分处不同微步。端口能表达数据依赖，表达不了对共享数据结构的时序依赖。

### 7. 微步稀缺

**设计理念**：微步表达因果先后，是强约束；能用数据依赖表达时不用时序。

同一 tag 内的先后优先用端口依赖表达，只有真正需要区分因果的场合（索引写入后读取、链式结算）才使用微步。微步泛滥会让执行顺序变成隐式约定，难以推理。

### 8. 结算在同 tag 内收敛

**设计理念**：同一时刻发生的事实必须共享同一时刻，不能因链深跨时刻。

链式反应由微步推进，直到不再产生新工作。收敛防护两层：流程类型之间声明的启动关系必须构成无环图（设计约束，主要防护）；单实体单流程类型在单次结算内的执行次数上限（运行时兜底，超限抛错而不是静默截断）。

### 9. 技能效果在施法前摇统一产生

**设计理念**：全部技能效果共用同一条延迟通路，不出现第二套时序。

技能生命周期为读条前摇、读条（咏唱或蓄力）、施法前摇、施法、施法后摇。效果计算统一发生在施法前摇，此时产生的伤害段与区域创建全部作为延迟事件交付：多段伤害按段间隔调度到各自的 tag，均分后的段伤害在结算时一次锁定，不逐段重算。
